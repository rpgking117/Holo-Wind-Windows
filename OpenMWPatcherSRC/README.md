# OpenMW SDL2 Capture Proxy — Build Instructions

## What this builds

`SDL2.dll` — a proxy DLL that replaces the real SDL2 in an OpenMW installation.
It intercepts OpenMW's rendering and input so OpenMW can run headlessly inside
the Fallout 4 Pip-Boy screen (Hollo-Wind project).

Every frame, it reads the OpenGL framebuffer, scales it to 876×700, and writes
it to a Windows named shared memory segment (`MorrowindPipboyBridge`) where the
Fallout 4 F4SE plugin picks it up. Input (keyboard, mouse) flows the other way
through the same shared memory.

## Files

### Source files (required to build)

| File | Role |
|---|---|
| `build.bat` | Main build script — run this to produce `SDL2.dll` |
| `pipboy_capture.c` | C source compiled into `SDL2.dll` — contains all interception and frame capture logic |
| `generate_proxy_def.py` | Reads `SDL2_orig.dll` exports and generates the `.def` files the linker needs |
| `SDL2_orig.dll` | The real SDL2, copied from the official OpenMW install — the proxy forwards all non-intercepted calls to this |
| `MorrowindBridge.h` | Defines the shared memory bridge layout that `pipboy_capture.c` mirrors |

### Generated by the build

These files are produced automatically when `build.bat` runs. You do not need to
create or edit them.

| File | Role |
|---|---|
| `SDL2_orig.def` | Export definitions for `SDL2_orig.dll` — used to build the import library |
| `SDL2_proxy.def` | Export definitions for the proxy DLL — tells the linker which functions to intercept vs. forward |
| `sdl2_forwards.h` | Auto-generated pragma forward hints (not used by the build, kept as reference) |
| `SDL2_orig.lib` | Import library for `SDL2_orig.dll` — lets the linker resolve forwarded calls |
| `SDL2_orig.exp` | Linker export file for `SDL2_orig` (build artifact) |
| `pipboy_capture.obj` | Compiled object file from `pipboy_capture.c` (build artifact) |
| `SDL2.lib` | Import library for the proxy `SDL2.dll` (build artifact) |
| `SDL2.exp` | Linker export file for the proxy (build artifact) |
| `SDL2.dll` | **The output** — the capture proxy DLL (~68 KB) |

## Prerequisites

**MSVC Build Tools (x64)** — Visual Studio 2019 or newer.

Install via: Visual Studio Installer → Individual Components → any "MSVC v14x C++ x64/x86 build tools".

`build.bat` uses `vswhere.exe` (ships with VS 2017+) to locate the correct
`vcvars64.bat` automatically — no Developer Command Prompt needed and no
hardcoded VS paths.

**Python 3** — required to run `generate_proxy_def.py`.
Optionally install the `pefile` package (`pip install pefile`) for faster export
reading; otherwise the script falls back to `dumpbin.exe` from MSVC.

## Getting SDL2_orig.dll

`SDL2_orig.dll` must come from the **official OpenMW 0.50.0 installation**. A copy
from OpenMW 0.50.0 is included in this folder.

To get it from a fresh OpenMW install:
1. Download and install OpenMW from https://openmw.org
2. Go to the OpenMW install directory (e.g. `C:\Program Files\OpenMW`)
3. Copy `SDL2.dll` into this folder and rename it to `SDL2_orig.dll`

## How to build

1. Open File Explorer and navigate to this folder.
2. Click the address bar, type `cmd`, and press Enter — this opens a Command Prompt
   in the correct directory.
3. Type `build.bat` and press Enter.

The script initializes MSVC, generates the `.def` files, compiles `pipboy_capture.c`,
and links `SDL2.dll`. The whole process takes a few seconds.

## Deploying the output

The built `SDL2.dll` goes into the **main OpenMW installation directory** (where
`openmw.exe` lives), replacing the original `SDL2.dll`. The original must be kept
alongside it under the name `SDL2_orig.dll` so the proxy can forward calls to it.

```
OpenMW install directory:
  SDL2.dll      ← our capture proxy (the file built here)
  SDL2_orig.dll ← the original SDL2.dll from OpenMW, renamed
  openmw.exe
  ...
```

OpenMW loads `SDL2.dll` (the proxy), which in turn loads `SDL2_orig.dll` for all
non-intercepted SDL2 calls.

## Updating for a different OpenMW version

If targeting a newer OpenMW release, drop its `SDL2.dll` into this folder renamed
as `SDL2_orig.dll`, then run `build.bat` again. The `.def` files are always
regenerated from whatever `SDL2_orig.dll` is present.
